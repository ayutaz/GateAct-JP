# 研究記録

実測した結果だけを書く。失敗した条件も残す。数値はすべて HF validation の対象内 2,826 件
(test)の値で、epoch とハイパーパラメータは dev(train から切り出した 2,613 件)だけで選んだ。

## 問い

1. 論理ゲートだけの回路(Griffith DLGN)で、日本語の文 → 16 クラスの Action 分類がどこまでできるか。
2. 既存の n-gram 分類器と比べて、精度・誤作動・サイズ・ESP32-S3 での速度に利益があるか。

## 2026-11-20: M2 初回スイープ(1 seed、10 epoch)

設定は `configs/lut/*.json`、実行は `scripts/sweep_m2a.sh`、結果は `results/lut/`。

### 観察 1: LUT2(difflogic の 2 入力ゲート)は 71% にとどまった

| 条件 | test exact | Macro-F1 | False Action | no_action Precision |
|---|---:|---:|---:|---:|
| LUT2、512 bit、4,096 + 4,096 ゲート、lr 0.01 | 71.37% | 0.359 | 0.40% | 67.85% |
| 同、lr 0.05 | 69.57% | 0.332 | 0.20% | 65.65% |

- dev の soft 精度と hard 精度はほぼ同じ(epoch 10 で 0.687 / 0.705)。**離散化で落ちたのではなく、
  soft の段階で学習できていない**。
- False Action Rate が低く見えるが、no_action の Precision が 68% と低い。多くの依頼を
  no_action と答えて「動かない」側に倒れているだけで、良い結果ではない。
- 仮説: 入力は疎なベクトル(validation の実測で 512 bit 中平均 47.8 bit = 9.3%、1024 bit で
  4.8%、2048 bit で 2.4%)で、2 入力ゲート 2 段では
  1 つの出力ゲートが見るのは最大 4 bit。クラススコアは「4 bit の論理関数 256 個の和」に限られ、
  少数の n-gram の有無で決まるクラスを拾いにくい。

### 観察 2: LUT4 / LUT6(warp パラメータ化)で大きく改善した

| 条件 | test exact | Macro-F1 | False Action |
|---|---:|---:|---:|
| LUT4 warp、512 bit、4,096 + 4,096 | 86.84% | 0.743 | 1.59% |
| LUT6 warp、512 bit、4,096 + 4,096 | **90.80%** | 0.852 | 1.85% |
| LUT2、512 bit、8,192 × 3 層 | 84.71% | 0.632 | 1.59% |
| LUT2、1024 bit、8,192 × 3 層 | 79.51% | 0.501 | 0.86% |

- 1 ゲートの入力数を増やす(LUT2 → 4 → 6)と大きく上がる。LUT2 は層を深くすると上がるが、
  入力を 1024 bit にする(より疎になる)と下がった。
- 学習時間(10 epoch、Apple M1 CPU、他の処理と並行): LUT4 297 s、LUT6 1,038 s、LUT2 3 層 約 250 s。

### 観察 3: 特徴量の衝突が上限を決めている可能性

同じ特徴ビットに線形層をかけた bit-linear は、入力幅で 93.54%(512)→ 95.97%(1024)→
96.85%(2048)と上がる。n-gram 分類器(65,536 バケット × 40 次元の埋め込み)は 98.76%。
入力幅を広げるだけで線形モデルが 3 point 以上上がるので、512 bit ではハッシュの衝突による
情報の損失が大きいと考えられる(LUT 回路が非線形性で線形モデルを上回れるかは未検証)。
